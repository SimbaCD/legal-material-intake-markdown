# Material Intake Markdown Workflow

## 1. 先建案件文件夹骨架

优先先起一个固定结构，再往里填材料，避免边处理边随意堆文件。

建议先运行：

- `scripts/init_case_folder.py --case-name [案件名] --output-dir [输出目录]`

## 2. 先盘点，再 OCR

默认顺序：

1. 运行 `python scripts/intake_case.py [材料目录]`
2. 主入口脚本自动检查环境变量、当前目录 `.env/mineru.env`、Skill 目录 `.env/mineru.env`
3. 提交 MinerU、下载 Markdown、生成规范目录和清单
4. 标记无法确定来源、日期、版本、OCR 质量或材料性质的文件
5. 交付下游分析 skill

快速执行纪律：

- 盘点先统计文件名、扩展名和目录位置，不逐份打开内容。
- 图片证据默认生成图片证据索引，不强行解释图片事实。
- 不搜索 `_tmp_*` 或缓存目录，除非用户明确要求复用上次结果。
- 不在案件目录或临时目录生成一次性组装脚本；材料组装只使用 `scripts/intake_case.py`。
- 旧的 `init_case_folder.py` 和 `build_manifest.py` 只作维护辅助，不是正常执行入口。
- 如果 MinerU 结果已经取得，后续只做整理、命名、复核标记和清单，不回头重复 OCR 探测。

默认优先使用 MinerU API Auto 模式：

- 有 `MINERU_API_TOKEN` 时走精准解析 API
- 无 Token 时提示用户配置，不伪造 OCR 结果
- Token 和默认参数可放在环境变量、当前目录 `.env/mineru.env` 或 Skill 目录 `.env/mineru.env`
- 保密材料、API 不可用或超出限制时，回退本地 MarkItDown / PyMuPDF / Umi-OCR
- 不要为单个案件现场生成大型转换脚本；按官方 API 提交、轮询、下载 Markdown 即可

如当前环境没有可用 OCR 或转换工具：

- 在材料清单中写明 `OCR 待处理` 或 `转换待处理`
- 不生成伪正文
- 继续处理其他可转换材料

如当前环境有 Umi-OCR / PaddleOCR-json，优先用其管道接口调用底层 OCR 引擎，不要启动 GUI 主程序。若直接命令行 OCR 对中文路径不稳定，可将中间图片复制到临时 ASCII 路径处理，但材料清单和 Markdown 头部仍必须记录原始文件路径。

## 3. Markdown 优先级

优先做成 AI 易读文本，不追求版面一比一复刻。

优先级：

1. `md`
2. `html` 仅在版面信息重要时
3. `svg` 仅在图表或页面定位重要时

## 4. 文件命名

处理后的 Markdown 必须重新命名，文件名至少体现材料产生时间、分类和材料名称。

默认格式：

- `YYYY-MM-DD-分类-材料名称.md`

如果原始文件没有日期，可以用：

- `未明日期-分类-材料名称.md`

命名时按以下顺序确认材料产生时间：

1. 材料正文中的落款、签署、发送、出具、形成或拍摄时间
2. 原文件名中的日期
3. 文件元数据或用户提供的材料说明
4. 仍无法确认时标为 `未明日期`

排除规则：

- 当事人出生日期、护照日期、身份证明日期不是材料产生时间。
- 授权委托书优先取落款或签署日期，不取委托人出生日期。
- 账单、报告、证明、声明优先取 `日期`、`出具日期`、`签署日期`。

不要为了让文件名看起来整齐而编造日期。分类应与 `materials/` 下的目录一致；同名文件追加 `-01`、`-02`。

## 5. 分类建议

- `A_法院及仲裁机构文件`
- `B_当事人主张材料`
- `C_当事人提交的证据材料`
- `D_第三方客观材料`
- `E_律师制作文书`
- `F_AI过程文件`
- `Z_待人工复核`

法院或仲裁机构形成的文件归入 `A_法院及仲裁机构文件`。起诉状、答辩状、申请书、情况说明等当事人陈述或诉讼主张归入 `B_当事人主张材料`。合同、付款凭证、聊天记录、邮件、照片、录音整理等当事人提交的证据归入 `C_当事人提交的证据材料`。银行流水、公证书、鉴定意见、评估报告等第三方形成的材料归入 `D_第三方客观材料`。代理意见、质证意见、证据目录等律师工作成果归入 `E_律师制作文书`。AI 和 OCR 中间结果归入 `F_AI过程文件`。

## 6. 待人工复核的典型情形

- OCR 错字明显
- 页码或表格错位
- 扫描件模糊
- 手写、盖章、图片证据识别不稳
- 材料来源、形成时间、版本或证明对象暂时无法判断

## 7. 交给下游前最少要有的东西

- `00_材料清单.md`
- `01_阅读顺序.md`
- `materials/` 下的 Markdown 文件
- 清单中能看到原文件、处理后路径、分类、OCR 状态和引用建议
- 待复核事项已经在清单或材料头部标明
